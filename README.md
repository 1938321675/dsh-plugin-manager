# DSH 插件管理器

一个独立的 Windows 桌面程序，用来管理 DeepSeek Harness 的第三方插件：按安装时间列出来、查看启用状态、手动开关。

它是为了解决一个很具体的麻烦：**装了个新插件，DSH 起不来了，只能手动去翻配置文件找到它、改成禁用、再重启。**

---

## 它解决什么

DSH 的插件开关写在 `~/.dsh/profiles/<profile>/cordis.patch.yml` 里。这个文件上千行，混着内核组件配置、模型目录、皮肤设置。插件一出问题、DSH 打不开，就得手工在里面找那一条记录改成 `disabled: true`。

这个程序把这件事变成点一下开关。

它不依赖 DSH 运行——DSH 完全打不开时，它照样能启动，并帮你禁用出问题的插件。

---

## 主要功能

| 功能 | 说明 |
|---|---|
| 插件清单 | 列出所有第三方插件，按安装时间从新到旧排列 |
| 最近安装 | 顶部单独一块列出最新 5 个，刚装坏的一眼看到 |
| 启停开关 | 每行一个开关，点一下即切换并写入配置 |
| 状态显示 | 已启用 / 已禁用 / 状态动态 / 目录缺失，如实区分 |
| 冲突识别 | 正确识别插件与内核 row 的归属关系，不会张冠李戴 |
| 启动监控 | 由程序启动 DSH 并观察，进程崩了立刻弹救援面板 |
| 崩溃救援 | 列出最可疑的几个插件，勾选后一键禁用并自动重试 |
| 可配置观察时长 | 启动观察期可设 10–600 秒，默认 180 秒 |

## 运行要求

- Windows 10 / 11
- PowerShell 5.1（系统自带）
- Node.js（用于解析 YAML，`node` 需在 PATH 中）
- WebView2 运行时（Windows 11 自带；Win10 若缺失需单独安装）

本程序已内置所需的两个库，不需要 `npm install`：

- `lib/webview2/` —— 微软 WebView2 托管 SDK
- `lib/yaml/` —— YAML 解析库（ISC 许可）

程序本体约 1.5 MB。

## 怎么用

双击 `启动.vbs`（或为它创建快捷方式）。

界面顶部是插件统计和搜索框，中间是插件列表，底部状态栏显示 DSH 是否在运行、配置文件路径、最后修改时间。

**改插件开关**：直接点行尾的开关，改完提示「重启 DSH 后生效」。

**DSH 打不开时**：找到「最近安装」里最上面的那个插件，把开关关掉，重新打开 DSH。

**用「启动 DSH」按钮**：程序帮你启动并观察。进程崩了会弹救援面板，列出最可疑的 3 个插件，勾上点「禁用并重试」就会自动处理并再启动一次。

**调整观察时长**：点「设置」填秒数。装了很多插件的机器，DSH 启动到弹出界面要一分多钟，观察期要覆盖这段等待，否则正常启动会被误判成失败。

## 实现说明

### 写入方式：只追加，不重写

配置文件的写法是在末尾追加一条记录：

```yaml
# --- dsh-plugin-manager 2026-11-02 17:25:16 (dsh-cost-meter) ---
- id: cost-meter
  disabled: true
```

这利用了 Cordis patch 层的语义：同一个 `id` 出现多次时，后面那条覆盖前面那条。

选择追加而不是重写整份文件，是因为原文件有一千多行、含深层嵌套的模型目录，用 YAML 序列化器整份重写会改变格式、丢注释。追加对文件其余部分零影响。

### 状态判定：两层 patch 合并

Loader 的条目来自两层：各 bundle 自带的 patch，然后才是 profile 的 patch。所以一个 row 的最终状态是「bundle 给的默认值」被「profile 的覆盖」替换后的结果。

只读 profile 层会漏判：有些插件在自己的 patch 里就把部分 row 关掉了（比如 dsh-ops 的 panel、tui 默认关闭），那是插件的出厂设计，不代表整个插件被禁用。

程序按以下规则判定：

- profile 层明确禁用 → 判定已禁用（这是用户意图）
- 只有 bundle 默认关的 row → 仍算启用，但在详情里如实列出是哪几个可选功能
- 全部 row 都关 → 才算已禁用

### row 归属：只认 insert

判定一个插件拥有哪些 row 时，只认它自己 patch 里 `insert` 出来的条目。

不带 `insert` 的 `- id: xxx` 是「覆盖别人已有条目的 config」，不算新建。例如 dsh-unlag 覆盖了内核的 `hmr` 配置，但 `hmr` 属于内核——如果把这种覆盖也算进它的 row，界面会显示错误归属，关掉 unlag 时还可能误禁内核热重载。

### 写入安全

四道防线：

1. **写前备份**：备份到 `data/backups/`，保留最近 20 份（同秒内多次操作会加序号，不互相覆盖）
2. **写后回读校验**：重新解析整份文件，确认该 row 最终状态等于期望值，否则自动用备份还原
3. **坏文件保护**：配置无法解析时拒绝写入，避免在已经坏了的文件上继续追加
4. **异常隔离**：单个插件解析失败只标记该行，不影响整份列表

### 安装时间为什么准

包的目录创建时间会在重装、升级时刷新，直接用它排序会打乱历史顺序。

程序在 `data/plugin-registry.json` 里记录每个插件「本地第一次见到」的时间，之后只认这个值，所以升级重装不影响排序。

### 界面为什么用 WebView2

界面的消息处理跑在 WebView2 的 UI 线程上。最初在消息回调里同步执行 node 并等待结果，界面每次都「后端无响应」——因为 `WaitForExit` 占住了 UI 线程，而结果又要靠同一个线程送回页面，直接互锁。

现在拆成非阻塞两步：回调里只登记请求立刻返回，一个 150ms 的定时器负责启动 node 并在下一拍收结果。全程没有阻塞等待。

请求用队列而不是单值变量：界面启动时 `settings` 和 `load` 几乎同时发出，单值变量会让后到的覆盖先到的，先发的请求就永远没人处理。

### YAML 解析的一个坑

解析 `cordis.patch.yml` 时不能用 `logLevel: 'silent'`。它会把**语法错误也一起静默**：一个缩进错误的畸形文件，正常解析会抛异常，加上 silent 后会被「成功」解析成垃圾结构。对写入模块来说这是灾难——损坏的文件会被当成合法文件接受，然后在上面继续追加。

正确做法是注册 `!!js` 自定义标签（patch 文件允许 `disabled: !!js ...` 这类表达式），让真正的语法错误照常抛出。

## 文件结构

```
dsh-plugin-manager/
├── 启动.vbs                 启动入口（隐藏控制台窗口）
├── start.ps1                启动前的环境准备
├── 使用说明.md              面向使用者的完整说明
├── src/
│   ├── app.ps1              窗口、消息处理、定时器
│   ├── bridge.js            PowerShell 与 Node 之间的数据交换
│   ├── ui/index.html        界面
│   └── core/
│       ├── plugins.js       插件发现、安装时间
│       ├── state.js         状态计算、row 归属
│       ├── writer.js        追加式写入、备份、校验
│       ├── settings.js      设置读写
│       ├── launcher.js      启动监控、崩溃判定
│       ├── yaml-lib.js      YAML 解析入口
│       └── index.js         数据聚合
├── lib/
│   ├── webview2/            WebView2 托管 SDK
│   └── yaml/                YAML 解析库
├── tools/                   验证与测试脚本
└── data/                    运行时产物（不入库）
```

## 测试

`tools/` 下是可重复运行的验证脚本：

| 脚本 | 作用 |
|---|---|
| `probe.js` | 只读打印所有插件及其状态 |
| `verify-rows.js` | 交叉验证 row 归属，检查有无张冠李戴 |
| `test-write.js` | 在副本上测试写入往返、备份、损坏文件保护 |
| `test-live-toggle.js` | 在真实配置上做一次往返（结束自动还原） |
| `test-launcher.js` | 验证崩溃检测的三种判定 |
| `dump-state.js` | 导出状态 JSON |

```powershell
node tools/verify-rows.js
node tools/test-write.js
node tools/test-launcher.js
node tools/test-live-toggle.js
```
